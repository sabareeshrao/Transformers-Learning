# TL-001 — Establish the Transformer Input Tensor Contract

**Day:** 1 / 365  
**Status:** Complete

## Engineering Problem

Transformer models do not receive raw words directly. After tokenization, they operate on numeric token IDs. Before embeddings, attention, or model architecture can be implemented, we need a clear tensor contract for those token IDs.

For this first step, the contract is:

```text
input_ids shape = [batch_size, sequence_length]
input_ids dtype = torch.long
```

**Decision:**

Start with a tiny PyTorch input layer that:

1. accepts one sequence of token IDs,
2. converts it to `[batch_size, sequence_length]`,
3. requires `torch.long`,
4. exposes batch size and sequence length,
5. rejects invalid shapes and dtypes.

## Why This Matches the Reference Direction

The Hugging Face Transformers codebase repeatedly obtains model input shape from `input_ids.size()`. Our implementation is intentionally much smaller, but it teaches the same core idea: downstream model code depends on the shape contract of `input_ids`.
