# TL-002 — Convert Raw Text into Vocabulary-Backed Token IDs

**Day:** 2 / 365  
**Status:** Complete

## Engineering Problem

Day 1 established the model-side contract:

```text
token IDs
    ↓
torch.long tensor
    ↓
[batch_size, sequence_length]
```

But a user does not normally start with token IDs. They start with text.

For Day 2, the missing boundary is:

```text
raw text
    ↓
tokens
    ↓
vocabulary lookup
    ↓
token IDs
    ↓
Day 1 tensor contract
```

The goal is not to build a production Hugging Face tokenizer in one day. The goal is to establish the smallest deterministic text-to-id path and understand why vocabulary lookup and an unknown-token fallback exist.

**Decision:**

Implement a deliberately small `SimpleTokenizer` that:

1. receives an explicit vocabulary,
2. requires an `[UNK]` entry,
3. lowercases and whitespace-splits text,
4. converts tokens to stable IDs,
5. maps unseen tokens to the unknown ID,
6. rejects empty text,
7. reuses Day 1 `build_input_ids()` for tensor creation.

## Why This Matches the Reference Direction

The reference Transformers codebase exposes token-to-id conversion as a vocabulary operation. For example, tokenizer implementations define `convert_tokens_to_ids(...)` specifically to convert token strings into integer IDs using a vocabulary.

Our implementation is intentionally smaller. It does not claim to reproduce Hugging Face tokenization behavior. It isolates the same architectural boundary so later days can evolve it naturally.
